## Stack and build

Native macOS app: Swift 6 + SwiftUI, deployment target macOS 15.0. No external runtime dependencies — images via ImageIO (JPEG/PNG/TIFF/HEIC), PDF via PDFKit, cropping via CoreGraphics. Tests use Swift Testing (`import Testing`).

The Xcode project is generated by XcodeGen from `project.yml` (`IdFit.xcodeproj` is gitignored — edit `project.yml`, never the project). Xcode is used via `DEVELOPER_DIR` set in the Makefile, so no `xcode-select` setup is needed.

- `make build` — regenerate project and build Debug
- `make run` — build and launch the app
- `make test` — run unit tests (single test: append `-only-testing:IdFitTests/<SuiteName>/<testName>` to the `xcodebuild test` invocation)
- `make package` — Release build, signed, into `dist/` (`VERSION=` and `BUILD=` stamp the bundle, `SIGN_IDENTITY=`/`CODESIGN_FLAGS=` switch ad-hoc signing for a Developer ID)
- `make icon` — regenerate `AppIcon.icns` from `Tools/make-icon.swift` (the result is committed; only rerun when the artwork changes)
- `make clean` — remove build artifacts and the generated project

Layout: app code in `Sources/IdFit/`, tests in `Tests/IdFitTests/`.

CI is GitHub Actions on `macos-26`, which is the image carrying Xcode 26 — the sources do not compile under Xcode 16, so the older `macos-15` image is not an option even though the app deploys back to macOS 15. Tests run on push and pull request, and a release when one is published on GitHub (`.github/workflows/release.yml`). Publishing is the trigger, not tagging — by the time the workflow runs the release exists, so it attaches the build to it rather than creating one, and the tag it was published from is the version. Distribution is the reason a few build settings look the way they do — the Release configuration turns on the hardened runtime because notarization requires it, and `make package` archives with `ditto` because Apple's notary service rejects anything else. Without a Developer ID the release is ad-hoc signed, which macOS blocks when a browser downloads it; `install.sh` sidesteps that by fetching with `curl`, which never sets the quarantine flag.

To open the app straight onto a folder while developing: `open build/Build/Products/Debug/IdFit.app --args /path/to/folder`.

The Finder Services entry and *Open With* rely on LaunchServices knowing the bundle. A Debug build is not registered automatically, so after changing `NSServices` or `CFBundleDocumentTypes` run:

```sh
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f build/Build/Products/Debug/IdFit.app
```

## Architecture

`DocumentStore` (`@MainActor @Observable`) is the source of truth for one open folder: it owns the folder, the `ProjectState`, and every mutation. Views never touch the file system; services never touch app state.

One window is one folder, so there is a store per window and none for the app. `DocumentWindow` creates it, and `.focusedSceneValue(\.documentStore, …)` is how the File menu knows which one it is talking about — scene-scoped rather than `focusedValue`, which waits for something inside the view to take keyboard focus and a grid of pages may never give it any. Anything genuinely app-wide lives outside the store: updates in `UpdateController`, and `OpenDocuments` — a weak list of the open stores, used to ask each window about unsaved work before the app quits. Nothing unregisters itself there: a window that closes lets go of its store and it drops out, whereas doing it from `onDisappear` removed stores that were still alive, SwiftUI being free to take a view down and put an identical one back up.

- **Model** — `ProjectState` is exactly what the folder's `.idfit` document holds: an ordered `[Page]`, each pointing at a `SourceRef` (relative file path + optional `pdfPage` index), plus the document-wide `cropAspectRatio`. `reconciled(with:)` merges saved state with what is currently in the folder: new files are appended, and pages whose file is missing are **kept**, because a partially-synced folder must not destroy crops.
- **A common format is asked for, never assumed.** `cropAspectRatio` nil is the *mixed* mode, not an unanswered question: every page is framed on its own at whatever shape suits it, and that is where every folder starts. Drawing a rectangle crops that one page (`drawCrop`); edge detection hands each page its own detection as-is. Choosing a format from `AspectRatioMenu` — or promoting one page's framing with `useFramingAsCommonFormat` — holds every page to it, refitting the crops that exist and centring one on the pages without. Going back to mixed **keeps** the crops and simply stops constraining them. `transposedRatio` says which way round a page holds the shared shape, so nothing sets it while mixed; a straightened page with no shared shape is mapped onto the one its own corners describe (`DocumentQuad.naturalAspect`).
- **Nothing is written until somebody saves.** Opening a folder only reads it, so a folder that was looked at is a folder that was not modified. `saveDocument()` (⌘S, or the toolbar button) creates the document, named after its folder by `StateStore.documentName(for:)`; a folder that already has one keeps that name, including the old `Document.idfit`. `hasDocument` gates every other write path — `scheduleSave`, which debounces bursts of edits by 400 ms, and `saveImmediately`, which flushes on quit — so autosave only starts once there is a document to keep up to date. Two actions write one without being asked: recording an export made into the working folder, and applying crops to the originals. Both have just changed the folder's contents, and the state describes that change. Work that was never saved is guarded by `confirmDiscard`, a closure the app fills in with an NSAlert and which is left nil everywhere else, so tests never block on a modal.
- **Crop coordinates** — crops are stored normalized (0…1 of the source), but the ratio the user cares about is the ratio of the *exported pixels*. Converting between the two always needs the source's pixel size, which is why `CropGeometry` takes a `sourceSize` everywhere and `DocumentStore` prefetches `sourceSizes` on open. Rotation flips the required source aspect (`sourceAspect(outputRatio:rotation:)`).
- **Rotation spaces** — the crop is stored on the *unrotated* source. The crop editor and grid previews work in rotated space and convert with `CropGeometry.rotated(_:by:)`; export applies crop first, then rotation.
- **Tilt is a crop that lies at an angle.** `Page.tilt` turns the page by a fine angle under a crop frame that stays upright, and everything downstream reads it through `TiltGeometry.derivedQuad` — the crop rotated by *−tilt* about its own centre, in **pixel space**, because rotation does not commute with normalized coordinates on a source that is not square. That quad then takes the straightening road (`PerspectiveCorrector`), which is why a tilted PDF page has to be rasterized just as a straightened one does. A turned rectangle needs more room than the crop itself, so every crop of a tilted page passes through `TiltGeometry.fitted` — the single place that clamping is written, sliding the crop back inside where it can and shrinking it about its centre only where it cannot. Tilt and `quad` are mutually exclusive: corners already encode any angle, so starting to straighten absorbs the tilt into the quad and zeroes it, and a fresh detection replaces it with the angle it measured — or with nothing, when it found no lean to speak of.
- **PDF handling** — PDF pages are read and drawn through their **crop box**, not the media box. Applying a crop to an original PDF narrows its crop box, so the app must read the same box back or it would show the page uncropped and crop it a second time. A warp or a fine turn cannot be said in a crop box, so applying one replaces *that page* with the corrected pixels and leaves every other page of the file vector — a file whose pages the document never mentions is not touched at all. The replacement page is sized from the region of the original it covered, never from the pixel count the warp happened to land on, so the page still prints at the size it always did. Rasters go into a PDF as JPEG (`ImageWriter.jpegBacked`), which CoreGraphics embeds verbatim: the same page costs a tenth of what its raw bitmap costs, and the export exists to be printed or emailed.
- **Caching** — `SourceGeometry` and `ThumbnailProvider` are singletons whose keys include the folder path and the file's modification date (`SourceCacheKey`), so same-named files in different folders and files changed by cloud sync don't collide.
- **After applying to originals** the crops in state are cleared and caches invalidated — otherwise the next export would crop the already-cropped file again.
- **One scan, two pages, two files.** A passport cover is both the front and the back of the finished document, so the same file stands behind two pages framed differently — and one file cannot be rewritten to answer both. `OriginalsWriter.divide` settles it in one place, used by the writer and by the confirmation sheet so the numbers it shows are the ones the run produces: the first page on a source keeps the file, and every other page on it is given a copy of its own beside it (`scan-2.png`, counting on until the name is free). A page that was never framed spills too when the page that kept the file was, because the file underneath it is about to stop being what it was looking at. The copies are written **first** — one made after the rewrite would read a file that already carries somebody else's crop and bake a second one on top — and a copy that fails blocks the rewrite of the file it came from, so a framing is never destroyed for want of somewhere to put it. `Result.newSources` is how the document follows its pages to their new files; without that the two would point at one file again with a single framing between them. This used to be refused outright and reported as a failure, which left the second framing nowhere to go.
- **Edge detection** uses `VNDetectDocumentSegmentationRequest` (Vision, system-provided). It returns a tilt-following quadrilateral in normalized coordinates measured from the bottom-left; crops are upright rectangles measured from the top-left, so `DocumentEdgeDetector` takes the enclosing box and flips y. **A sheet lying crooked is proposed as an angle rather than boxed**, because the box around it holds the slivers beside it as well: when the four edge directions agree to within `maximumEdgeSpread` the corners are a rectangle merely lying over, and `tiltProposal` hands back that lean negated into `Page.tilt` together with the corners turned upright and boxed — the document's own rect. Angles are measured in pixels (`TiltGeometry.lean`), normalized coordinates shearing them on a source that is not square; the spread is what tells a crooked scan from one photographed at an angle, which no single turn can put right. The angle is asked for first and the corners take what is left: a quad subsumes a tilt, so the two would describe the same rectangle, but a sheet that only needs turning is turned with one slider instead of four corner drags — and `straightenByDefault` being **on** would otherwise mean the angle was never offered again. Straightening is where a shape no single turn can put right goes. A detection covering more than `maximumCoverage` of the scan is dropped: on a featureless image the model reports the whole frame, and acting on that would trim a page that needed no crop. Pages carry `autoDetected` so a deliberate "no crop" survives reopening while a scan added later still gets a suggestion.
- **Updates** install themselves. `UpdateChecker` asks GitHub for the latest release and compares it with the bundle's version; `UpdateInstaller` fetches the archive and puts it in place of the running app. Replacing a live bundle is where a self-updater goes wrong, so the order is: download, unpack, refuse anything whose bundle identifier or version is not what was promised, refuse anything whose signature does not verify, and only then one atomic `replaceItemAt` — staged through `.itemReplacementDirectory` so it lands on the same volume and cannot degrade into an interruptible copy. A helper waits for the app to exit and reopens it, because relaunching from inside races the app's own quit. Every failure path leaves the installed copy untouched and falls back to the release page. The look on launch runs at most once a day (`UpdateSchedule`) and stays silent both when there is nothing new and when it fails: being offline is not news. It announces through Notification Center (`UpdateNotifier`) so that arriving to work on a document is not interrupted by a modal; if notifications are refused it falls back to the alert, because news that cannot be delivered must not simply vanish. A check asked for from the menu always answers in the window instead — a question said out loud deserves an answer on the spot. "Later" records nothing: the daily interval is the whole of the snooze.
- **One alert, many notices.** `ContentView` funnels every post-action message through a single `.alert` and a `Notice` case, in a stated priority order, rather than one `.alert` modifier per message. Only one can be on screen at a time regardless, so this makes which one a decision written in the code rather than a consequence of the order the modifiers happen to sit in. Add a case, not a modifier. **A failure speaks first**, `store.lastError` being the reason nothing else happened: an export or an apply that goes wrong has no result to report, and for a long time it reported nothing at all, which read as the app quietly refusing to save. The welcome screen shows the errors it can raise in place, so the alert only speaks for a window with a folder open.
- **Guidance is said once.** The line under a page in the editor (`EditorHint`) names the gesture that page is waiting for, and each kind is shown once: it fades out on its own after a few seconds, or on the capsule's close button, and is then remembered as read in one defaults key for every window. Advice that returns on every page stops being read and becomes something to look past — which is how it was reported. *Show Hints Again* in the editor's **More** menu is the way back, so nothing is lost for good. The capsule stands over the bottom of the page and answers to the pointer only on that button: a crop drawn from there must reach the canvas, not the advice about drawing it.
- **Opening from outside** takes two roads. Finder's *Open With* and `open -b …` are delivered by SwiftUI to a window through `.onOpenURL`; handling them in `AppDelegate` instead makes macOS open a window for the request and SwiftUI open a second one beside it. The Services menu and the folder named on the command line have no window to arrive at, so `AppDelegate` routes them: an already-open folder just gets its window activated, anything else gets a window of its own through the `openWindow` action a window lends to `OpenDocuments`, and a folder that arrives before any window exists waits for the first one to take it. `openFolder` still serializes overlapping requests.
- **Launching opens nothing.** No folder is reopened and no window is restored: the app starts on the welcome screen, which is where the recent folders are. Closing the last window leaves the app running, as a document app should.

## Testing approach

Export correctness is verified by rendering the produced PDF back to pixels and sampling colours (see `PDFExportTests`), which is the only reliable way to catch flipped, mirrored or misplaced output. Prefer that over asserting "it didn't throw".

## What ID Fit is

A local macOS application (macOS-only for now) for organizing scanned documents. The user points it at a folder full of scan files (e.g. 20 A4 scans of a passport, possibly with mixed page sizes, resolutions, and DPI), and the app provides a UI to:

- reorder pages of the document;
- crop each file individually — at its own shape by default, or all to one shared aspect ratio when the export has to come out uniform;
- export the result to PDF (for printing or emailing).

## Hard constraints (from README)

- **Source files are never modified by default.** Edits (crop, ordering, etc.) live only in app state. Actually touching the originals happens only via an explicit, separate user action — either "apply changes to real files" or "export modified files to a separate folder", or ⌘⌫, which sends the file behind a page to the **Trash** (`moveToTrash(pageIDs:)`) and takes every page standing on it with it. That one is not confirmed twice: the Trash is the confirmation, as it is in Finder.
- **All state persists to a visible `.idfit` document (JSON) inside the working folder.** The folder plus this file must be fully portable: if the folder syncs through the cloud to another computer, opening it there in ID Fit must restore everything (order, crops, etc.). This implies no absolute paths and no state outside the folder.
